# AI赋能高考平台 Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** 把错题网升级为以高考母题检索、八步知识卡、真题辨识训练和教师备课为核心的学生—家教—学校平台。

**Architecture:** 保留现有 Python/SQLite 单体以快速验证，在全卷分析流水线内增加独立的高考领域层。领域层负责母题匹配、证据标识和八步知识卡；RAG资料、真题授权数据与用户数据分离，未来可平滑迁移至向量检索服务。

**Tech Stack:** Python 3、SQLite/FTS5、Vanilla JavaScript、现有OCR与大模型服务。

---

## 发展路径

1. **0—3个月：核心闭环。** 全卷上传、笔迹还原、错因、纠错思路、评分点、母题模型、提醒、辨识训练、自我复盘；学生与教师双视图。
2. **3—6个月：数据壁垒。** 建立约300个经教研审核的母题条目；导入有授权的30年真题与模考题，逐题保存出处、年份、地区、答案、评分点、解法和易错点；上线审核台和版本管理。
3. **6—12个月：服务闭环。** 上线50课时家教套餐、教师备课教案/PPT、学生复习计划、家长周报、教师对学生的任务和批改。
4. **12—24个月：To B与多终端。** 学校租户、班级学情、校本题库、SSO和审计；移动端扫码上传。硬件仅在学校合规与真实需求验证后立项。

## 架构决策

- **ADR-1：先模块化单体，不拆微服务。** 当前验证速度与运维成本优先；当检索数据超过百万题或并发任务成为瓶颈时再拆OCR队列和检索服务。
- **ADR-2：真题必须带来源。** AI生成训练只作为补充且明确标识，不能冒充历年真题；题目正文须确认版权或授权范围。
- **ADR-3：AI结果可复核。** 低置信度、无母题命中、评分点缺失均标为待复核，教师可修订后沉淀。
- **ADR-4：不承诺替代教师。** 产品定位为降低备课与复盘成本，最终教学判断保留给教师。

## 实施任务

### Task 1: 高考领域模型

**Files:** Create `gaokao_core.py`; Test `test_gaokao_core.py`

- 编写母题匹配、来源标识和固定八步知识卡测试。
- 实现种子题型目录与确定性匹配。
- 未命中时进入人工复核，不伪造真题来源。

### Task 2: 接入全卷分析

**Files:** Modify `server.py`; Test `test_gaokao_core.py`, `test_paper_workflow.py`

- 初始化种子母题。
- 每道非正确题在AI诊断后匹配母题并生成 `gaokao_card`。
- 将母题命中统计写入全卷摘要。

### Task 3: 学生与教师界面

**Files:** Modify `web/app.js`, `web/index.html`, `web/styles.css`

- 在每道错题展示母题编号、来源状态和讲话定义的八步知识卡。
- 将“母题预留”改为正式母题中心，展示公式、提醒和来源。
- 教师模式提供教案导出入口和待复核提示。

### Task 4: 验证与发布

**Files:** Modify `deploy/scripts/deploy-edu-full-paper.py` as needed

- 运行全部单元测试和脚本语法检查。
- 用数学、英语、综合测试卷验证上传、母题匹配、八步卡和导出。
- 备份生产数据后发布，执行健康检查与线上API抽查。

## 非功能要求与风险

- 学生笔迹和试卷属于敏感教育数据：最小权限、租户隔离、可删除、访问审计。
- OCR、模型或检索失败时保留原图和原文，允许重试及人工复核。
- 对“985家教”“50课时”“1万元”等商业承诺建立合同、退款、教师资质与未成年人保护流程后再开放支付。
- 评价指标：错题提取准确率、母题Top-3命中率、评分点完整率、教师备课耗时、7/30日掌握率，而非仅统计生成次数。
